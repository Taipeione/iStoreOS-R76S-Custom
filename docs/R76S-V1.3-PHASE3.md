## 5. 后续执行顺序

1. 先固化候选源码/来源记录，明确首启认证策略和只测试入口；不得使用现有自动发布工作流进行 feature 验证。
2. 执行全测试及新的 defconfig 选项检查，再启动单次候选完整编译；记录耗时、镜像信息与 Stage25 实际审计。
3. 在可恢复的 R76S 测试设备按 B → C → D → E 顺序逐模块验收，保留每模块前后配置快照。
4. 备份后执行 F 的 V1.2.2 升级/恢复测试，再执行稳定性测试；失败先分析，不自动回滚。
5. P0/P1 关闭并形成完整证据后再决定正式发布。**本次准备没有授权创建 Release、改 main 或启动现有发布工作流。**

只读本地检查入口：`R76S_JOBS=4 bash build/local-arm64/candidate-local.sh check`。未来候选编译可用同脚本 build 模式，但须事先明确凭据模式；默认私有模式需独立密码，私有镜像不能发布。`R76S_PUBLIC_RELEASE=1` 只是构建凭据策略，不代表允许发布，且当前有 P0 默认密码风险。

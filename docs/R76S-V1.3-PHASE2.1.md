# R76S-V1.3 Phase2.1：IPv4 only 与 IPv6 防绕过

本阶段继续在 feature/R76S-V1.3 实现，不修改 main，不编译或发布。
本说明替代 Phase2 文档中“尚无 IPv6 防火墙”的状态。

## DNS 分类与兼容性

SmartDNS 默认公网规则抑制 AAAA，保留 A。国内域名列表、微信/腾讯的 24 个
已有直连域名保留 A/AAAA。腾讯列表逐项对比 PassWall 和 PassWall2 的 ROM
WeChatDirect + TencentMediaDirect 域名集合；不调整原 41 条基础规则及顺序。
例外支持子域名，微信/腾讯不依赖是否出现在 chnlist 中。

独立策略只追加自己的 SmartDNS include，仍不重建上游、不自动接管 DNS。
正常 DNS 链路须经过这套 SmartDNS 策略；其他外部 DNS、DoH 或应用内部的
解析回答不受它控制。IPv6 出站过滤用于补上缓存/硬编码地址绕过这一层。

## 出站保护

工具：/usr/libexec/r76s/r76s-ip6-guard。
独立 nftables 表：inet r76s_ip6_guard。forward/output 钩子优先级 -5，阻断
未允许的全球 IPv6 目的地址，包括 router 自身出站和 LAN 转发。IPv4 不过滤，
不使用 established/related 或代理 mark 的全放行规则，也不触碰 PassWall 表。

允许范围：

- PassWall 或 PassWall2 的 chnroute6 国内 IPv6 CIDR。
- SmartDNS 将国内及微信/腾讯 AAAA 回答写入 direct6 集合。
- 明确配置的 LAN 出接口、回环、ULA、链路本地、组播以及必要 ICMPv6 控制。

同一 IP 可服务多个域名，IP 白名单无法区分共享 CDN 上的国内与国外站点。
严格模式不允许国外 IPv6 代理/WireGuard 端点；这些端点需要 IPv4 地址。
不通过全局关闭 IPv6 来解决问题；LAN/国内 IPv6 保持正常。

## Cache 与 reload

实测当前 SmartDNS Release48.4 缓存命中不会重新填充已经丢失的 nftset 元素。
因此启用防绕过时，仅对国内和腾讯域名附加 -no-cache，确保每次回答写入
允许集合。全局缓存和国外 A 缓存不改。代价是这些域名的上游查询量增加。
仅 DNS 策略模式不附加此选项。

重载只刷新自己表的链和 CN CIDR 集合，保留动态 direct6 元素及超时。
保留最后有效规则到 /etc/r76s-ip6-guard/last-good.nft。预检/输入异常时
重新加载最后有效规则；若恢复文件也缺失，加载严格模式并报错，不静默放开
全球 IPv6。此故障状态下部分国内 IPv6 也可能暂时受限，需要修复数据。

## 启用、停止与恢复

默认配置 /etc/config/r76s_ip_policy 的 ipv6_guard=0；出厂不会启用保护。
先手动启用 SmartDNS、配置 cn/foreign 组及实际 DNS 链路，关闭软件与硬件
flow offloading，移除其他 flowtable，再执行：

```sh
/usr/libexec/r76s/r76s-ip6-guard check
/usr/libexec/r76s/r76s-ip6-guard enable
```

enable 会备份 SmartDNS/firewall/独立配置及现有保护表，检查 nft 语法后
加载独立规则，添加唯一的 fw4-compatible script include，重新加载 firewall
和 SmartDNS。出错恢复本次变更前的配置与保护表。不会覆盖两套代理配置。
目录锁阻止同时执行启用/停止。最后有效规则、独立配置及 DNS include 纳入 OTA。

S17 初始化在 SmartDNS S18 之前创建 nftset；firewall 重载后通过 include 重新
加载保护表。单独停止 init 服务不删除保护，避免误操作打开出站路径。

```sh
/usr/libexec/r76s/r76s-ip6-guard disable
```

disable 移除自己的 firewall include/table，去掉 DNS 配置中的 nftset 写入，
保留 DNS 的国外 AAAA 抑制。保护启用时，不允许单独移除其 DNS 策略。
异常断电留下操作锁时应先审查备份和当前状态再人工处理。

## 自动测试

- UCI/服务模拟：默认无操作、启停幂等、卸载拒绝、nft 失败、服务失败恢复。
- 数据异常：最后有效规则恢复及无恢复文件时严格过滤。
- 两套配置和规则输出保持基线；腾讯列表等于两套直连规则的域名集合。
- 隔离容器实际 kernel nftables：输出/转发的国外 IPv6、已建立 UDP 会话、
  代理 mark 和后续 accept 不能绕过；国内 IPv6 与 IPv4 可通过。
- 实际 SmartDNS：国内 A/AAAA、国外 A/无 AAAA、微信/腾讯 AAAA、动态 nftset
  写入、集合丢失后的重填、reload 后保留微信放行。
- Lua 页面语法、状态分类、OTA 逻辑及既有 DNS/恢复回归。

实际包测试在 --network none 的临时容器内进行，仅虚拟网卡和私有 nftables。
没有启动完整编译或修改设备。完整 PassWall/PassWall2 DNS/透明代理联动、
实际 WAN IPv6、重启/断电和 OTA 仍需后续镜像及实机验收。

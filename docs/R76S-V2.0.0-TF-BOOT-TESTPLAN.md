# R76S-V2.0.0 TF 独立启动测试计划

## 安全边界

本测试只使用独立、可擦除的 TF 卡。禁止执行 `sysupgrade`、`dd` 到任何板载设备、USB/RKDevTool 刷写、MASKROM、`EraseAll` 或 eMMC/SPI 操作。

正式版本的 TF Artifact 是 OpenWrt RK3576 完整磁盘镜像的字节一致复制品。OpenWrt 目标生成器使用 `pine64-img` 组合 SPL/U-Boot、kernel 分区和 rootfs 分区；它不包含 FriendlyELEC EFlasher 安装包。

## 写卡前检查

1. 在独立 Linux/macOS 主机上确认 TF 设备节点，拔除其他可移动磁盘。
2. 仅把 `openwrt-...-tf-boot-test.img.gz` 解压为普通 `.img` 后写入 TF；人工复核目标设备，不允许使用 `/dev/mmcblk*` 或生产盘作为主机写入目标。
3. 用 `SHA256SUMS` 校验压缩文件和解压后的记录；保存原始 V1.4.6 配置备份。
4. 不使用 FriendlyELEC `eflasher`、`-sd-to-eMMC`、`-usb` 或 Web eMMC Tools 流程。

## 首次启动

1. 关闭 R76S，保持 eMMC 和 SPI 原样，插入 TF。
2. 首次启动接入 3.3V UART，参数为 1500000 8N1；同时观察 SYS、LAN、WAN LED。
3. 镜像默认 U-Boot `boot_targets` 为 `mmc1 mmc0`；R76S DTS 别名为 `mmc1=sdmmc`（TF）、`mmc0=sdhci`（eMMC）。
4. 进入系统后只读确认：`/proc/cmdline` 的 `root=PARTUUID=...`、`findmnt /rom`、`lsblk`、`/sys/firmware/devicetree/base/compatible`、`ubus call system board`。
5. 只有确认 `/rom` 和 rootfs PARTUUID 来自 TF 后，才接入隔离网络。

## 功能验收

- NanoPi R76S / RK3576 / kernel 6.12.112 / DTS。
- 双 RTL8125BG、LAN `192.168.50.1/24`、PPPoE、IPv4、IPv6。
- dnsmasq、ChinaDNS-NG、AdGuard Home、SmartDNS、Xray DNS。
- PassWall、PassWall2、Xray、Sing-Box、WireGuard、DDNS、Docker。
- AppleEcosystem 85 条规则、十组应用规则、WeChatDirect TCP/UDP 直连。
- 重启后规则、网络、服务和配置持久化。

## 恢复原系统

测试结束前关机并拔出 TF，再重新上电。由于本测试镜像和 CI 打包步骤不写 eMMC/SPI，正常情况下 U-Boot 会跳过不存在的 `mmc1` 启动项并继续 `mmc0` eMMC。必须以 UART/LED 和原 LAN 地址实际确认恢复结果；在此之前不得把恢复标记为通过。

# R76S-V2.0.2 恢复指南

## 重要边界

普通 LuCI/SSH OTA 不写 SPI，不执行 MASKROM，不调用 EraseAll，也不自动刷写生产设备。
任何需要 USB/RKDevTool、`upgrade_tool`、MASKROM 或 EraseAll 的流程都不是普通 OTA，必须人工确认。

## 无串口的正常恢复路径

- 如果系统仍能从 eMMC 启动并可访问网络，先通过 LuCI 备份/升级或 SSH 保存配置和日志，再重新执行
  同布局 OTA。
- 如果系统还能正常启动但需要验证新系统，使用独立 TF 测试镜像；关机拔出 TF 后，原 eMMC 启动链
  才能恢复。是否恢复必须以实际设备 LED、LAN 和网络访问确认。
- 如果只是 LuCI 页面异常但 SSH 可用，使用本项目 `r76s-ota check/download/verify/install`。

## TF 救援

FriendlyELEC 文档说明 R76S 可以从 TF 启动；本项目 TF 镜像不包含 EFlasher，不会自动安装到 eMMC。
但本项目没有把 TF 启动标记为实机已验收，必须先完成独立 TF 启动测试。

## 无法保证的故障场景

若 eMMC 上的 U-Boot/SPL、SPI 启动链或分区表已损坏，网络和普通 LuCI/SSH 都可能不可用。
FriendlyELEC 官方恢复流程要求按住 MASK 键进入 MASKROM，并使用 USB/RKDevTool 或 Linux
`upgrade_tool`；该流程可能擦除 eMMC，不能由本项目自动执行，也不能保证无需串口或无需另一台电脑。

因此“日常版本升级无需 UART”成立，但“所有升级失败都能无需 UART 恢复”不成立。

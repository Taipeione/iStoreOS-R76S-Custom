# R76S-V2.0.0 Apple ecosystem rule group

## Source and maintenance

`config/rules/apps/apple.txt` is a separately maintained `AppleEcosystem` rule group. Its source is Apple Support’s official [Use Apple products on enterprise networks](https://support.apple.com/en-us/101555) page, published/updated 2026-08-07 in the source page currently audited for this project. The source URL and date are retained as comments in the input file.

The selection covers the Apple services explicitly listed by Apple for device setup, APNs, App Store and content, software updates, Apple Account/iCloud, Apple Intelligence/Siri, and Apple developer content. Apple’s unpublished CNAMEs are intentionally not guessed or expanded. The selection uses explicit hosts and narrowly scoped Apple-published wildcards such as `*.icloud.com` and `*.push.apple.com`; it does not use the unverified broad `*.apple.com` pattern.

## Routing and priority

The group is additive and has no `node`, `outbound`, or `strategy` option. It therefore follows the active PassWall/PassWall2 system default outbound strategy; it does not force `DIRECT` or `PROXY`.

The 43 baseline rules retain their original order. Application groups, including `AppleEcosystem`, are inserted immediately before the legacy final `TencentMediaDirect` rule. `WeChatDirect` remains the first rule, explicitly covers TCP and UDP, and remains mapped to `_direct`. The Apple group cannot overwrite an existing user-named section during migration.

## Build, migration, and OTA paths

- Import/audit source: `scripts/r76s-import-app-rules.py`
- Generated manifest: `config/rules/r76s-app-rules.json`
- Firmware default: `/usr/share/r76s/r76s-app-rules.json`
- Build-time PassWall and PassWall2 defaults: pinned `0_default_config` files
- Runtime additive merge: `/usr/libexec/r76s/r76s-rules-merge.lua`
- Migration entry point: `/usr/libexec/r76s/r76s-config-migrate`

The merge is section-name additive: existing user sections win and only missing named rules are appended. A source audit or generated default file is not proof of runtime migration success; that status remains pending until both PassWall and PassWall2 UCI runtime configuration are inspected on a booted test device.

## Audit fields

The generated audit records Apple’s domain count, blank/comment lines, file duplicates, cross-file duplicates, format errors, manifest path, runtime merge path, and insertion priority. The current imported project state is complete for the 11 rule inputs: AppleEcosystem plus the ten user-provided TXT groups. Duplicate source entries are preserved as non-blocking audit warnings.

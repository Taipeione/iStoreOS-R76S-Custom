# R76S-V1.3 第一阶段

基线：R76S-V1.2.2；开发分支：feature/R76S-V1.3。

## WireGuard

使用固定 LuCI feed 的 `luci-proto-wireguard`，包含接口/Peer 编辑、客户端
配置导入、标准配置生成、二维码和“状态 → WireGuard”。显式选择
wireguard-tools、kmod-wireguard、luci-lib-uqr、ucode；该版本用浏览器生成
二维码，不需要旧 luci-app-wireguard 或额外 qrencode 包。

- 客户端：在“网络 → 接口”添加 WireGuard VPN，导入服务端提供的标准配置，
  检查 Endpoint、AllowedIPs、地址及防火墙区域后保存。
- 服务端：创建 WireGuard 接口、独立隧道地址、监听 UDP 端口和每设备一个
  Peer。只为需要访问的网络配置转发；需要外部访问时手动添加对应 UDP 入站
  规则，并检查上游 NAT 转发。固件不预设接口、密钥、开放端口或默认路由。
- iPhone：在 Peer 中设置客户端私钥、地址、公网 Endpoint 和 AllowedIPs，
  使用“生成配置”二维码导入官方 WireGuard App。
- Windows：将同一标准 `[Interface]` / `[Peer]` 配置保存为 `.conf`，在官方
  WireGuard 客户端导入。每个设备使用独立密钥及不冲突的隧道地址。
- NAT 后的客户端按需设置 PersistentKeepalive=25。DNS 填写客户端通过隧道
  实际可访问的地址；不自动修改路由器 DNS。

参考：
https://openwrt.org/docs/guide-user/services/vpn/wireguard/server
https://openwrt.org/docs/guide-user/services/vpn/wireguard/client

## AdGuard Home

“服务 → AdGuard Home”入口由现有 luci-app-r76s-status 包安装，不依赖 YAML
已经存在或服务已经启动。页面只读，检查二进制、init 脚本、procd/进程、
启动项和两种已有 YAML 路径。干净刷机默认关闭，升级保留原有服务状态。
不新增 DNS 接管、自动初始化或监听端口配置。

## OTA

最终模板为 build/local-arm64/v12-overlays/ota/index.htm。仅调整标题、步骤
说明和样式，保留原 JavaScript、API 和 DOM ID。当前/远端版本仍读取真实
状态，不把旧设备或旧远端版本伪装成 V1.3。固件身份、镜像名、元数据和检查
同步到 R76S-V1.3，保留 SHA256、metadata、sysupgrade -T 和恢复机制。

## 验证边界

第一阶段不运行完整编译，不触发 Actions 或发布。工作流仍只允许 main 分支
运行，开发分支推送不会自动编译。41 条基础分流规则顺序及两条直连组保持
基线行为。首启密码、DNS 八模式和规则拆分问题不在本阶段改动范围。

后续固件验收必须覆盖：WireGuard 客户端/服务端握手、iPhone 扫码、Windows
配置导入、LAN 路由与 NAT、AGH 未配置/关闭/运行状态、保留配置升级和 OTA
校验失败。源码验证不代表已通过实机兼容性验证。

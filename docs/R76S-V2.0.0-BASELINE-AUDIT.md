## Hardware and boot-chain finding

The official 25.12.6 image profile uses `generic-rk3576` U-Boot and the upstream `rk3576-nanopi-r76s.dts`. The DTS covers the RK3576 SoC, SD/eMMC aliases, PCIe, USB, LEDs, reset key and the two RTL8125-connected network paths through the upstream `r8169` driver package.

OpenWrt issue #26051 reports that 3GB/no-eMMC R76S boards fail to boot the official 25.12.5, 25.12.6 and snapshot TF images, while FriendlyWrt boots. The issue points to an RK3576 SD-card BootROM alignment/boost workaround that was present in OpenWrt main after the 25.12.6 tag. Until a serial-console boot test is completed on the exact board variant, this is a hardware-blocking risk, not a pass condition.

No eMMC is written by the V2 build scripts. The first hardware test must use a spare TF card and preserve V1.4.6 recovery media.

## Rule baseline discrepancy

The checked-in V1.4.6 manifest currently contains 43 names, in order, ending with `TencentMediaDirect`; the generator asserts exactly 43. This is observable in `config/rules/r76s-rules.json` and commit `f4095a6`.

The execution brief says historical records contain 32 names and forbids inventing nine more. V2 therefore does not invent, pad, or silently delete rules. The build audit will report the exact 43-name repository baseline, and the user must resolve the 32-versus-43 discrepancy before a stable release. `WeChatDirect` remains an explicit TCP+UDP `_direct` rule; the broad `domain:qq.com` rule is forbidden.

# V1.4.0 架构

`config/r76s-release.json` 描述版本及验证范围；`r76s-sources.lock.json` 固定依赖来源；`config/rules/r76s-rules.json` 是规则数据来源。构建后的 manifest 另外记录当前源码提交。

LuCI status/updater 的 feeds 文件为唯一页面源码。Stage14 不再生成并覆盖页面；Stage15 保留经测试的旧控制器适配，Stage16 最后执行 `r76s-v14-stage.py` 安装签名后端及原生服务适配。旧迁移阶段为 V1.2.3 兼容保留，不应在未验证迁移前直接删除。

`r76s-core` 提供服务协调、DNS 事务、OTA、迁移、健康检查和 Endpoint 恢复。原生代理内核与 nft 生成仍由锁定的 PassWall/PassWall2 管理，R76S 不另写一套透明代理规则。

服务持久意图以 global UCI enabled 为主，启停、开机及恢复时同步 init 链接。直接手工改 UCI 后可运行 `r76s-service-manager reconcile`；临时停止不更改持久意图。仅使用 ACL/SOCKS 的高级配置须单独检查其启动行为，不应将 global 关闭等同于所有独立实例关闭。

默认 DNS 为 dnsmasq:53→WAN；显式选择 SmartDNS:6053、AGH:3053 或组合链路。管理器只恢复自己改动的 dnsmasq 上游字段，不覆盖之后修改的 DHCP 租约/地址配置。上游组不被删除或重建。DNS 模式恢复不等于卸载或清空服务配置。

IPv6 guard 与 DNS 分类默认关闭。WireGuard 主机名需要 AAAA 时可加入 `r76s_ip_policy.main.endpoint_domains`；启用可选恢复后，以 `wg6` 超时集合放行精确的路由器 UDP Endpoint。隧道内地址族和路由仍按原生 WireGuard 配置管理。

稳定通道 `R76S-stable` 仅存签名 metadata，镜像由不可覆盖的版本 Release 提供。公钥随固件分发，私钥位于 Actions Secret；密钥轮换须先通过旧可信链分发新公钥。保留标准上传和 CLI sysupgrade 供管理员恢复，它们不等同于在线签名通道。

# R76S-V2.0.2 OTA 兼容性审计

## 结论

| 来源 | 直接 LuCI/SSH sysupgrade | 结论 |
|---|---:|---|
| V1.4.6 | 否 | 阻止。旧系统为 24.10.8、256 MiB rootfs、OPKG 和旧内核 ABI；目标为 25.12.6、512 MiB rootfs、APK 和 6.12.112。 |
| V2.0.x（含 V2.0.0/V2.0.1） | 是（仅静态门禁） | 同一 `rockchip/armv8`、NanoPi R76S、64 MiB kernel/512 MiB rootfs 几何；必须保留配置并通过全部检查，实机仍未验证。 |

OpenWrt 的 rockchip upgrade 脚本会比较当前与镜像分区表；分区不一致时会走整盘写入分支。因此不能把
V1.4.6 的 256 MiB 分区变化伪装成普通保留配置升级，也不能强制忽略设备检查。

## V1.4.6 的支持迁移方案

1. 在旧系统生成 `sysupgrade -b` 配置备份并下载到安全位置。
2. 使用独立 TF/官方完整镜像完成一次 V2.x 安装；该步骤不是普通 OTA，不得使用本项目的在线
   `sysupgrade` 路径。
3. 首次启动 V2.0.2 后，通过 LuCI 的配置恢复入口上传备份。
4. 项目选择性恢复网络、PPPoE、DNS、PassWall、PassWall2、SmartDNS、AdGuard Home、WireGuard、
   DDNS 和规则；不恢复 `/etc/opkg`、`/etc/apk`、`/etc/shadow`、旧 init/rc.d 或旧 OTA 状态。
5. APK 包和所有 kmod 按 V2.0.2 的新 ABI 重新安装。

## V2.0.x→V2.0.2 门禁

- 设备 Metadata 必须包含 `friendlyarm,nanopi-r76s`。
- Target 必须为 `rockchip/armv8`，OpenWrt 必须为 25.12.6。
- SHA256、签名、`fwtool` Metadata 和 `sysupgrade -T` 必须全部通过。
- `/tmp` 至少需要镜像大小两倍加 16 MiB 可用空间。
- 升级前自动备份配置；任何备份、服务冲突或启动盘检查失败都阻止刷写。
- 同布局路径不会主动重写不必要的 U-Boot/SPL/SPI；真实设备行为仍需硬件验收。

# V1.2.3 来源端升级说明（预发布，设备升级等待用户确认）

来源 Release 的 `r76s-ota-preserve-state` SHA256：
`38f92ae81a4998a4229638b4520fc5f37e91f7fd77cb7cc7d2f30e8df3a7c4d2`。
已与 V1.2.3 固定基线及维护补丁生成器逐字核对。

正常提交情况下，该 helper 支持状态保存及 V1.4 恢复；真实固件 UCI 模拟验证
全部七项状态组合，以及 PPPoE、IPv4/IPv6、WireGuard、DDNS、节点、订阅相关
配置、44 条测试分流规则、SmartDNS include 和 AGH YAML 的保留。

故障注入确认：当 commit 错误地返回 0 但没有落盘，来源 helper 的验证可能
读到未提交 delta 并误判成功。V1.4 中的脚本不能修复本次升级前运行的旧脚本。

验证设备升级时可采用标准 LuCI 上传并保留配置；这条路径由新镜像的标准
sysupgrade 保留配置检测/恢复钩子处理，不依赖旧自定义 OTA helper。
任何实际刷写仍需备份、可恢复 TF/UART 和用户确认，自动测试不证明实机兼容。

若要继续使用旧系统的自定义在线升级入口，应先在来源系统安装本预发布随附
的修复版 helper。以下步骤只供用户确认后的人工操作，本项目不会自动连接或刷机：

1. 下载预发布 helper、`sha256`、`ota.json`、`ota.json.sig`，验证来源和校验和。
2. 在路由器将旧 `/usr/libexec/r76s/r76s-ota-preserve-state` 备份到 root 私有目录。
3. 以 `sh -n` 检查新 helper，再替换原路径并设置 0755 权限。
4. 仅在真正发起升级时运行保存，不提前运行以免留下 pending 标记。

预发布不会成为 Latest，也不会修改稳定 OTA 指针，因此旧在线页面不会自动
将其视为正式升级目标。正式通道推广需另行确认。

默认 sysupgrade 保存 `/etc/config`，新增 keep list 还覆盖代理附属目录、
SmartDNS、AGH 标准 YAML、R76S 状态和 IPv6 策略。用户在标准路径之外的
自定义文件应显式加入 `/etc/sysupgrade.conf` 并验证备份清单。

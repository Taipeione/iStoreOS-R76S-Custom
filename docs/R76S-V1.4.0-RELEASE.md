# R76S-V1.4.0

基线为 V1.2.3 的 iStoreOS 24.10.8 / R76S 固定源码与 OTA 初始化修复，选择性保留并改造 V1.3 的 WireGuard、IPv6 和诊断模块。目标为 `friendlyarm,nanopi-r76s`、`rockchip/armv8`。

## 变更

- 分流规则改为独立 JSON 数据与生成器；保持 43 条规则、原有顺序及 24 个微信/腾讯直连域名，移除两个直连组之间的重复项。
- 新增服务协调包。正常启停与首启迁移同步 UCI/init 状态；两套透明代理不能同时开启。节点、订阅与用户规则保留。
- 新增显式 DNS 模式：默认 WAN DNS、SmartDNS、AGH、AGH→SmartDNS。启用前检查上游/查询；失败恢复配置。组合模式 AGH 故障可降级到 SmartDNS，全部高级解析失败时不静默泄漏到 WAN DNS。
- 国内双栈、国外 AAAA 抑制与可选 IPv6 出站 guard；基础设施主机可配置解析例外，WireGuard 端点只允许精确 UDP IPv6 例外。
- R76S 状态中心：CPU 采样、温度、内存、存储、WAN IPv4/IPv6、PD、服务配置/开机/运行状态。
- 保留原生 WireGuard 客户端/服务端编辑和 DDNS；提供客户端配置/二维码及可选 Endpoint IPv6 优先恢复。
- OTA 使用 Ed25519 签名 metadata、固定版本 URL、摘要/大小/设备/版本检查、sysupgrade -T、备份及恢复状态。稳定通道指针与固件资产分离。
- 阻止任意上游组件覆盖已测试的固件组件组合；组件升级请使用整包固件更新。
- 干净刷写首次启动默认 root 密码为 `password`；保留配置升级保留用户已有 root 密码，不覆盖认证信息。

## 升级

优先从 V1.2.3 下载固件后，通过标准 LuCI 保留配置升级；检查 SHA256。旧系统的升级前 helper 不会被尚未刷入的镜像修复，V1.2.2 用户应先按 V1.2.3 指南修复旧 helper。

新系统的在线升级验证固件内置公钥对应的签名。同版本与降级安装被拒绝；恢复旧版本请使用离线恢复流程并检查配置兼容性。

**干净刷写后请立即修改默认 root 密码。保留配置升级不会覆盖已有 root 密码。**

## 验证范围与限制

GitHub Actions 进行源码回归、完整编译、实际 SquashFS 文件/规则/服务检查，以及发布资产摘要、签名和 gzip/raw 一致性审计。

未执行 R76S 实机刷写、真实 WAN/IPv6、微信完整业务、手机二维码导入后的远端握手、断电恢复及 7 天长稳测试。Release 的生成不代表这些实机项目已经通过。`ota.json` 与 `BUILD-VALIDATION.txt` 明确记录该范围。

高级 DNS 与 IPv6 guard 默认关闭。纯 AGH 模式遵循用户上游，地址族分类需 SmartDNS 模式；foreign DNS 是否经过代理取决于上游配置，必须核对实际出口。共享 CDN IP 无法在 IP 层完全按域名区分。新 DNS 管理器支持两个标准 AGH YAML 路径；其他自定义路径须自行纳入 sysupgrade 备份。

恢复和验收流程见仓库 `docs/R76S-V1.4.0-RECOVERY.md`、`docs/R76S-V1.4.0-TEST-PLAN.md`。

# R76S-V2.0.0 Run #14 Failure Analysis

- Run: [42079746403](https://github.com/Taipeione/iStoreOS-R76S-Custom/actions/runs/42079746403)
- Commit: `4bff993a6a380775d534aa00796be925467c888b`
- Failed job: `OpenWrt 25.12.6 Build`
- Failed step: `Build official OpenWrt firmware`
- Stage: target package compilation

## First real blocking error

The custom package `luci-app-r76s-updater` attempted to install:

`root/usr/libexec/r76s/smartdns.bin`

The file was absent from the package source tree, producing:

`install: cannot stat .../luci-app-r76s-updater-1.4.1/root/usr/libexec/r76s/smartdns.bin: No such file or directory`

followed by:

`ERROR: package/r76s/luci-app-r76s-updater failed to build.`

The later `make world` exit code was a consequence of this package failure.

## Non-blocking messages excluded

The earlier `ninja` missing-file message, configure `not found` probes, package
mirror 404s, and the recursive dependency warning were not the first terminal
error. The log continued past those messages; the updater install failure was the
first error that stopped a package target and propagated to `world`.

## Classification

This was a build integration/source-staging omission. It was not a NanoPi R76S
DTS or RK3576 target failure, kernel ABI failure, PassWall/PassWall2 rule failure,
AppleEcosystem failure, WeChatDirect failure, or APK database failure.

## Safe repair

The build now stages the locked SmartDNS Release48.4 AArch64 runtime into the
updater source immediately before the custom package is copied into OpenWrt. The
archive is fetched from the official SmartDNS release URL, checked against the
locked SHA256, verified as gzip, unpacked, and required to contain an AArch64 ELF.
The updater package and SmartDNS functionality remain enabled; no core package or
rule group is removed.
